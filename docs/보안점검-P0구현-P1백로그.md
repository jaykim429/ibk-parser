# 보안·개선 점검 — P0 구현 결과 + P1 백로그

> IBK 규제변동 영향분석 앱 / 브랜치 `ibk-poc`

> 원칙: 최소·근본 수정, config 외부화, 새 모듈 0, fail-closed. (검토→설계→검증→재수정→재검증→완료 사이클)

## P0 — 구현 완료 (지금)

| # | 항목 | 변경 | 검증 |
|---|---|---|---|
| 1 | **임베딩 fail-closed** | `config.ts` `embeddingApiUrl` 외부 디폴트(OpenRouter) 제거 → 빈값. `embedding.ts` `embed()` 진입부 URL 미설정 시 즉시 throw | env 미설정 시 외부 호출 0건·명확한 에러 / env 설정 시 정상 ✅ |
| 2 | **서버측 업로드 크기 게이트** | `config.maxUploadBytes`(기본 30MB, env) 신설. `route.ts`에서 `arrayBuffer()` 전 `f.size` 조기컷 + 적재 후 `buffer.length` 실측 강제선 → 413 | 30MB 한도 확인(관측 최대 8.6MB 대비 여유 71%) ✅ |
| 3 | **전체 타임아웃 데드라인 + 클라 504 분기** | `config.pipelineTotalTimeoutMs`(기본 600s) 신설. `runPipeline`을 `Promise.race`로 감싸 초과 시 명확한 실패. `route.maxDuration` env 외부화(기본 600). `page.tsx` fetch에 `AbortSignal.timeout` + `res.ok` 분기(504/502/413 메시지) | 데드라인 경합 PASS(초과 시 '처리 시간 초과') ✅ |

**근거**: 셋 다 "배포하면 바로 깨지거나(임베딩·타임아웃) 한 사용자가 인스턴스를 묶는(업로드)" 실효 장애. 모두 인증과 무관한 **리소스·거버넌스 가드**라 부모 인증과 무충돌. tsc 0에러.

**중요(운영 종속)**: 타임아웃의 진짜 해결은 코드가 아니라 **리버스프록시 `proxy_read_timeout`/Node `requestTimeout` ≥ 600s**. 부모가 못 늘리면 그때 비동기 잡(202+폴링)을 정당화 — 지금은 보류.
