### 헤딩 트리(outline 20) — 단편화가 심함
```
- CA 채널 교차판매 운영매뉴얼
    - 메트라이프생명보험주식회사
    - 배                ← ⚠ "1 배경"에서 번호 '1 '이 떨어져 나가 "배"만 남음
    - 비즈니스 모델 개요
    - 위촉 / 교육 / 청약 / 커미션 / 해촉 / 관리   ← 키워드만 남은 절 제목
    - 5⟶가이드          ← ⚠ 번호+탭+제목이 "5\t가이드"로 뭉개짐
    - 8⟶프로세스 / 9 모니터링 / 10 부칙
    - (개행)필수(개행) / (개행)청약(개행) / (개행)구분(개행) / (개행)해촉(개행)  ← ⚠ 중복·개행 헤딩
    - (개행)시행일(개행)
```
→ 매뉴얼은 조문번호(`제N조`) 대신 **시각적 번호 섹션("1 배경", "5 가이드", "8 프로세스")**을 쓰는데, 번호와 제목이 분리되거나(`배`) 탭으로 뭉개지고(`5\t가이드`), 같은 제목이 개행 포함 중복(`\n필수\n`)으로 잡힌다.

## 3. 청킹(manualToChunks) 결과

```
needsSummary 0 · 공백붕괴 청크 1 · 연혁삽입 청크 1
임베딩텍스트(text 필드) 길이: max 933 (cap 2000) · 캡초과 0건
```

### ⚠ 가장 큰 문제 — 목차(TOC)가 9청크 노이즈로 인덱싱됨
청크 2~10 (약 880자 × 9개 ≈ 8,000자)이 전부 **점선 리더 목차**다:
```
청크#2 sectionId="… > 메트라이프생명보험주식회사" (886자)
  목차 | 1배경............ | | ............ | 4 | | 1.1 개념 ............ | 4 |
  1.2 목적 및 배경 ............ | 4 | | 2 비즈니스 모델 개요 ............ ...
청크#3~#10: "............ | 4 | | 2.2 교차조직 업무 R&R ............ | 5 |" (계속)
```
→ 목차 페이지의 점선·페이지번호가 그대로 9개 청크로 벡터화 → **검색 노이즈**(본문 아님). `메트라이프생명보험주식회사` 단일 섹션에 10청크가 몰린 것도 이 때문.

### 정상 동작한 부분
- **문서통제 헤더(표 #0)**: 깔끔히 추출 — `제정일/개정일=2025.01.02/2025.07.01`, `기안부서=CA이노베이션팀`, `전결권자=담당임원`
- **본문 섹션 그룹핑**: 목차 이후 `위촉`·`해촉`·`비즈니스 모델 개요` 등은 [문+표] 청크가 섹션별로 모임(예: `위촉`에 문2/표4, `해촉`에 문4/표3).
- **표 분리·캡**: 표 16개가 개별 청크, body ≤900 준수(거대표 꼬리손실 없음).

## 4. 근본 원인 & 개선 방향 (오버피팅·하드코딩 지양, 보편 적용)

| # | 문제 | 근본 원인 | 개선 방향 |
|---|---|---|---|
| 1 | **목차 누출**(9청크 노이즈) | 점선 리더 목차 페이지를 본문과 동일 취급 | 청킹 전 **목차 블록 감지**(점선 리더 `…{8,}` + 끝 페이지번호 비율 높은 연속 라인) → 인덱싱 제외 or 단일 메타청크화. *(범용 — 매뉴얼·보고서 공통)* |
| 2 | **헤딩 단편화**(`배`, `5\t가이드`, `\n필수\n`) | 시각 번호헤딩의 번호/제목 분리·탭·개행·중복 | 헤딩 정규화: 선행 번호+탭 재결합(`5\t가이드`→`5 가이드`), 개행 trim, 인접 동일 텍스트 헤딩 병합. *(manual-chunk 헤딩 처리 보강)* |
| 3 | **bill 오분류** | "운영매뉴얼/매뉴얼"이 policy·guideline 정규식 미포함 → 캐치올 | detectItemType에 매뉴얼류 인식 추가(입력 영향분석에선 영향 작으나 DB화 메타 일관성엔 유효) |
| 4 | **한글추출률 38%** | 표·점선목차 비중 | #1 해소 시 자동 개선(목차 제거 후 본문 비율↑) |

> 비교: 조문형 "기준·지침"은 `제N조` 헤딩이 명확해 위 #1·#2가 거의 없음. **비정형 매뉴얼(운영매뉴얼/안내서/매뉴얼)**이 목차·시각헤딩 때문에 청킹 품질이 가장 취약한 군이다 → DB화 적재 시 이 군에 목차/헤딩 정규화 가드를 우선 적용 권장.
